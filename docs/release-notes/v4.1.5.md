# v4.1.5 — 重复 DSML 分隔符流式识别修复

本次修订版修复模型输出 `<｜｜DSML｜｜calls>` 等重复竖线格式时，完整文本能够解析，但流式输出仍把工具标签当成正文返回的问题。

## 修复与行为

- 流式起始识别和批次闭合共用重复分隔符规则，支持单、双、多个竖线，以及全角 `｜`、半角 `|` 和两者混用，不再只匹配固定的单竖线前缀。
- 正确保留尚未完整到达的标记，兼容标签逐字符及任意位置分片；待定前缀受已有缓冲上限约束，普通竖线正文和未闭合标记可原样返回。
- 沿用共享 DSML 解析与筛分链，覆盖 Chat Completions、Anthropic Messages、Responses 的流式与非流式路径；保持工具参数、CDATA 和 Unicode 原文偏移。
- 限定扫描只能从连续竖线的起点尝试匹配，避免长段普通竖线在每个位置反复回溯；增加长竖线正文及后续真实工具标记回归。

## 验证与升级

- 新增及扩展 39 项测试，完整后端测试 361 项通过；路由矩阵覆盖三个端点、流式/非流式及单、双、混合竖线。
- Python 同步、Python 异步与 JavaScript OpenAI SDK 各 10 组 HTTP 回归通过。
- 真实 Codex CLI 通过逐字符双全角 DSML 工具回合，实际执行只读文件命令并回传结果；该项使用测试上游，另验证 `store=false` 及资源释放。
- 使用更新后的本地凭证进行一次真实 DeepSeek 流式工具请求，成功解析工具名和精确参数，未泄漏标签正文。单次成功样本不代表长期工具调用成功率，也不表示真实上游必然输出双竖线。
- 中英文验收文档和 `--dsml-variant` fixture 已同步为双全角格式。服务端、管理接口与 WebUI 包版本统一为 `4.1.5`，更新后重启服务即可。

当前范围与配置见 [Responses 中文指南](https://github.com/snake-aabb-wtf/deepseek-web2api-free/blob/v4.1.5/docs/responses-api.md)。本发布不包含 HAR、token、cookies 或临时验收账号配置。
