# v4.0.0 — 多模态图片输入与多轮上下文

本次大版本将图片输入接入 OpenAI 聊天补全和 Anthropic Messages。两种协议、流式与非流式共用图片校验、上传和会话准备链；同时修复思考流式短答案丢失，并补齐多轮图片、重试和取消处理。

继续使用 `deepseek-chat` 即可，不需要新增 `vision` 模型名。已有文字调用方式保持兼容。

## 新增图片输入

- **OpenAI `/v1/chat/completions`**：支持用户消息中的 `image_url`，可使用 base64 data URL 或公网 HTTP(S) 图片地址。
- **Anthropic `/v1/messages`**：支持 `image.source` 的 base64 和 URL 格式，包括用户 `tool_result.content` 内嵌图片。
- 支持**静态 JPEG、PNG、WebP**，图片可与文字、思考输出和多图输入组合使用。
- 图片由选定账号完成上传，使用上传专用 PoW；处理至 `SUCCESS` 后再提交聊天。客户端无需自行处理上游文件 ID、PoW 或轮询。
- 标准 OpenAI SDK 可使用 `client.chat.completions.create()` 和标准 `image_url` 消息格式，不需要为了发送图片而添加项目专用参数。

OpenAI 输入示例：

```json
{
  "model": "deepseek-chat",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "描述这张图片"},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,<图片base64>"}}
    ]
  }]
}
```

完整示例和配置见 [README 的图片输入说明](https://github.com/snake-aabb-wtf/deepseek-web2api-free/blob/v4.0.0/README.md#图片输入与多模态)。

## 多轮上下文与图片引用

- 历史比较包含图片内容哈希和顺序，能够区分“文字相同、图片更换”的请求。
- 固定会话中复用已上传图片，只上传新增图片；图片引用绑定调用方、账号和凭证指纹，避免跨账号或凭证更换后错误复用。
- 新建上游会话重试时保留可用的完整输入和图片引用，修复只发送最新图片时可能遗漏旧图引用的边界。
- 文件引用只在内存会话缓存中保留，不持久化图片字节；每个会话最多缓存 64 个引用。

多轮使用有两种方式：

1. **不传会话标识**：每轮发送完整 `messages`，包含历史文字和原图；服务端在新会话中重建上下文。
2. **复用上游会话**：每段对话固定使用 `X-Conversation-Id`，或 OpenAI `user` / Anthropic `metadata.user_id`。在缓存有效且账号可用时，可以只发送最新消息。账号切换或链无法复用时，客户端仍应重发完整历史和原图。

## 修复与资源处理

- **修复思考流式短答案丢失**：当答案全部位于新 `RESPONSE` 片段的首帧中时，也会立即输出正文，不再只返回推理内容。
- 新 `THINK` 片段自带的推理内容同样保留，并维持后续增量输出顺序。
- 上传、轮询和同步流读取在线程中执行，避免阻塞异步路由。
- 补齐准备期间取消、读取期间取消、SSE 发送取消，以及 `FINISHED` 或工具调用提前结束时的清理；先结束读取、关闭上游，再归还账号。
- 上传或图片处理失败在响应流开始前返回对应协议的 JSON 错误，不因普通图片输入错误而将账号标记为失效。

## 校验与默认限制

新增 Pillow 依赖，用于实际图片格式、声明 MIME、静态帧和像素大小校验。远程图片下载采用独立的无凭证连接，对 DNS、实际连接地址和每次重定向执行公网地址检查。

| 配置 | 默认值 |
| --- | --- |
| `IMAGE_MAX_IMAGES` | 每请求 8 个图片部件，包含历史及工具结果 |
| `IMAGE_MAX_BYTES` | 单图文件 10 MiB |
| `IMAGE_MAX_TOTAL_BYTES` | 每请求全部图片文件 32 MiB |
| `IMAGE_MAX_REQUEST_BYTES` | 两个聊天入口的 JSON 请求体 40 MiB |
| `IMAGE_MAX_PIXELS` | 单图 2500 万像素 |
| `IMAGE_DOWNLOAD_TIMEOUT` | 远程图片下载超时设置 15 秒 |
| `IMAGE_PROCESSING_TIMEOUT` | 每次上传 HTTP 请求及处理轮询分别为 60 秒；不包含 PoW、排队、重试和聊天 |

以上是本服务的资源策略，不代表上游最大能力。格式/内容错误、超限、上游限流及处理失败分别返回相应状态；详情见 README。

## 升级说明与已知边界

1. 升级后重新安装 `requirements.txt`；Windows 用户可运行 `start.bat` 更新依赖并启动。
2. 账号凭证仍通过 WebUI 账号池或 `data/accounts.json` 配置，不从 `.env` 读取。调用方使用项目生成的 API Key，不使用 DeepSeek 网页 token。
3. **公网 URL 的实际可用性受 DNS/网络环境影响**：验证环境把图片域名解析为 `198.18.*` 的 fake-IP 地址，两种接口均按策略拒绝并返回 400。URL 下载及防护代码通过离线测试，但尚无该环境中成功的公网 URL 下载证据。请使用真实公网 DNS，或发送已实测通过的 base64/data URL；程序不绕过地址校验，也不使用环境代理下载图片。
4. 不支持 system/assistant 图片、动画、PDF、音视频或公开 Files API 文件 ID。OpenAI `detail` 没有上游映射；`temperature`、`top_p`、`max_tokens` 仍是被忽略的兼容字段。
5. OpenAI 非流式 `usage` 为本地文字/附件标记估算，流式不发送 usage 块；Anthropic usage 仍为 `-1`。不提供准确视觉 token 或上游计费用量。
6. 图片引用寿命、任意视觉细节的长期回忆、长期运行及高并发稳定性不作保证；本项目仍依赖可能变化的 DeepSeek 网页私有接口。

本发布不包含 HAR、token、cookies、签名图片 URL 或临时验收账号配置。
